# الموت

یک پروژه برای صفحهٔ معرفی، پنل صاحب کالا و پنل راننده. بک‌اند داخل `src/server` است و هر دو پنل همان جدول `shipments` را می‌بینند. گفتگوی هر بار با وب‌سوکت روی مسیر `/ws` انجام می‌شود.

## اجرا

MySQL باید روی `127.0.0.1:3306` روشن باشد. فایل `.env` را از روی `.env.example` بسازید. دیتابیس پیش‌فرض `alamut` است و دیتابیس‌های قبلی پنل‌ها را عوض نمی‌کند.

```bash
npm install
npm run dev
```

سایت روی پورت `4179` و API روی پورت `5088` بالا می‌آید. از صفحهٔ اصلی دکمهٔ «ورود» دو راه دارد: رانندگان و صاحب کالا.

کد تأیید راننده در حالت توسعه `1234` است. کد صاحب کالا در پاسخ درخواست کد، فیلد `devOtpCode`، برمی‌گردد.

## پنل عملیات

مسیر `/admin` مرکز عملیات است. ورود با شمارهٔ از پیش تعریف‌شده و کد ثابت توسعه `12345` انجام می‌شود (تا وقتی `SMS_PROVIDER` برابر `kavenegar` نباشد).

| نقش | موبایل | کد |
| --- | --- | --- |
| مدیر سامانه | `09120000000` | `12345` |
| اپراتور دیسپچ | `09120000001` | `12345` |
| اپراتور امنیت | `09120000002` | `12345` |
| سرپرست بازرسی | `09120000003` | `12345` |
| پشتیبان مدارک | `09120000004` | `12345` |
| دیسپچ و امنیت | `09120000005` | `12345` |

رانندگان نمونه `09123000001` تا `09123000007` با همان کد `1234` وارد می‌شوند.

## پنل متصدی

مسیر `/inspector` برای متصدی میدانی است و برای گوشی چیده شده. ورود با شمارهٔ ثبت‌شده و کد ثابت `12345` است.

| متصدی | موبایل | کد |
| --- | --- | --- |
| متصدی بارگیری خیام | `09124000001` | `12345` |
| متصدی بارگیری عطار | `09124000002` | `12345` |

API موبایل روی `/api/v1/inspector` است: OTP، فهرست مراجعه‌ها، پذیرش، چک‌لیست، وزن باسکول، ارزش دقیق کالا، عکس پلمب و مهار، و ثبت گزارش. گزارش در همان `InspectionReport` پنل عملیات می‌نشیند و رویداد سفارش می‌سازد. تصمیم‌های باز بخش ۱۱.۴ در تنظیمات سامانه است: `inspector_required_mode`، `inspector_dispatch_payer`، `inspector_grace_minutes`، `inspector_no_show_policy`، `weight_discrepancy_kg`، `value_discrepancy_ratio`، `inspector_final_approval`، `inspector_required_items` و `inspector_checklist`. API موبایل راننده روی `/api/v1/driver` است: درخواست و تأیید OTP، تمدید توکن، فهرست و قبول مأموریت، تغییر وضعیت، ارسال دوره‌ای GPS، بارگذاری مدرک و عکس، و تأیید OTP تحویل. توکن دسترسی در هدر `Authorization: Bearer` می‌آید. نقشه و هشدار پنل عملیات از همین گزارش موقعیت تغذیه می‌شوند.

باری که صاحب کالا ثبت می‌کند با وضعیت «در جستجوی راننده» ذخیره می‌شود و در فهرست مأموریت‌های راننده دیده می‌شود. بعد از قبول بار، گفتگو بین همان دو نفر باز است.
