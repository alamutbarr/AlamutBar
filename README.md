# الموت — سامانه حمل‌ونقل و لجستیک

پیاده‌سازی فارسی و راست‌به‌چپ با **Next.js 16.4.5، React 19.3.1، Django 5.2.19 و MySQL 8.4**. صفحه عمومی از ظاهر و تصویر سایت [alamut.bar](https://alamut.bar/) الهام گرفته و چهار پنل به یک گردش کار واقعی در دیتابیس متصل‌اند.

## راه‌اندازی نسخهٔ تحویلی

آدرس محلی: **[http://127.0.0.1:3001](http://127.0.0.1:3001)**

```powershell
cd F:\alamut-delivery
pwsh -File scripts/start.ps1
```

چیدمان پوشهٔ تحویلی به این شکل است.

```text
alamut-delivery\
  frontend\apps\site\        لندینگ Next.js، صفحات عمومی و سئو
  frontend\apps\driver\      پنل راننده React + Vite
  frontend\apps\owner\       پنل صاحب بار React + Vite
  frontend\apps\inspector\   پنل متصدی React + Vite
  frontend\shared\            رابط، استایل، فونت و کد مشترک
  frontend\platform\          راه‌اندازی مشترک پنل‌ها و PWA
  backend\                    Django، API، ادمین و اتصال MySQL
  infra\                      تنظیمات انتشار nginx و TLS
  scripts\                    نصب، اجرا و تست محلی
```

هر فرانت‌اند `package.json` و فرمان بیلد خودش را دارد. فایل `.env`، رمزهای محلی، دیتابیس، آپلودها، وابستگی‌های نصب‌شده و خروجی‌های بیلد عمداً در بستهٔ تحویلی قرار نگرفته‌اند. برای نصب وابستگی‌ها، ساخت دیتابیس محلی و آماده‌سازی اولیه، ابتدا `pwsh -File scripts/bootstrap.ps1` را اجرا کنید.

اسکریپت، سایت، سه برنامه و بک‌اند را اجرا و اتصال به MySQL را بررسی می‌کند. سایت و برنامه‌ها روی پورت‌های ۳۰۰۱ تا ۳۰۰۴ هستند. Django محلی روی ۸۰۰۱ و MySQL روی ۳۳۰۷ اجرا می‌شوند. دیتابیس مستقل در `runtime/mysql` است.

| نقش | نام کاربری آزمایشی | پنل |
| --- | --- | --- |
| صاحب بار | `owner.demo` | [پنل صاحب بار](http://owner.localhost:3003/owner/app) |
| راننده | `driver.demo` | [پنل راننده](http://driver.localhost:3002/driver/app) |
| متصدی | `inspector.demo` | [پنل متصدی](http://inspector.localhost:3004/inspector/app) |
| اپراتور | `admin.demo` | [مدیریت Django](http://admin.localhost:8001/django-admin/) |

رمز سه حساب پنل `AlamutDemo!2026` است. رمز جداگانهٔ `admin.demo` در `runtime/local-admin.txt` روی همین سیستم ساخته می‌شود. اگر نصب محلی قدیمی است، `backend/.venv/Scripts/python.exe backend/manage.py seed_local_admin` آن را ایجاد می‌کند. `operator.demo` برای تست API استفاده می‌شود. برای انتشار واقعی، حساب کارکنان را با `create_portal_staff operator --django-admin` بسازید.

این حساب‌ها و هشت محموله اولیه، **نمونه و غیرواقعی** هستند. `driver2.demo` یک راننده کامیون با همین رمز است. داده‌هایی با نام «آزمایش یکپارچه» نتیجه تست HTTP هستند. داده‌های نمونه به API واقعی و MySQL متصل‌اند و تغییرات ذخیره می‌شوند.

```powershell
# نصب و راه‌اندازی از ابتدا در Windows دارای MySQL مسیر Laragon
pwsh -File scripts/bootstrap.ps1
# ساخت نسخه بهینه فرانت‌اند
pwsh -File scripts/build.ps1
# حالت توسعه
pwsh -File scripts/stop.ps1 -WebOnly
pwsh -File scripts/start.ps1 -Dev
# توقف وب و API همین پروژه
pwsh -File scripts/stop.ps1
# توقف دیتابیس مستقل پروژه هم به‌صورت graceful
pwsh -File scripts/stop.ps1 -Database
# تست‌ها؛ سرویس‌های محلی باید روشن باشند
pwsh -File scripts/verify.ps1
```

## پنل‌ها، صفحات عمومی و PWA

[ورود و نصب برنامه‌ها](http://127.0.0.1:3001/apps) · [مقالات](http://127.0.0.1:3001/articles) · [درباره ما](http://127.0.0.1:3001/about) · [راهنمای پنل‌ها](http://127.0.0.1:3001/help)

سه پنل React نشانی، آیکون، شناسهٔ نصب و نشست مستقل دارند. حالت آفلاین راهنمای اتصال را نمایش می‌دهد. نصب روی گوشی به یک نشانی HTTPS قابل دسترسی نیاز دارد.

درباره ما، خدمات، روش همکاری، مقالات، پرسش‌های قابل جست‌وجو، تماس، پیگیری، راهنمای نقش‌ها، نصب، امنیت، شرایط و وضعیت سرویس تکمیل شده‌اند. اپراتور با مجوز `content` از «مقالات و محتوا» پیش‌نویس و انتشار را مدیریت می‌کند. چهار راهنمای اولیه با فرمان `backend/.venv/Scripts/python.exe backend/manage.py seed_content` بدون بازنویسی محتوای موجود ساخته می‌شوند.

[گزارش اصلاحات و راهنمای PWA](docs/PANEL_AUDIT_PWA.fa.md) جزئیات خطاها، محدودیت‌ها و آزمون‌ها را توضیح می‌دهد.

## امکانات تکمیلی این نسخه

- فونت وزیرمتن WOFF2 محلی، اندازه‌های خوانا و تقویم شمسی.
- ثبت‌نام مرحله‌ای راننده، مدارک خصوصی و بررسی مستند اپراتور با کنترل انقضا.
- نقشه و رصد GPS با رضایت راننده، زمان اندازه‌گیری، دقت و هشدار موقعیت قدیمی.
- اتاق کنترل، CRM، تاریخچه ارتباط، مسئول و پیگیری‌های سررسیددار.
- رخداد بحرانی، پرداخت بخشی، دفترچه نشانی متصل به فرم بار.
- ورود دومرحله‌ای TOTP، بازیابی رمز با صف ایمیل رمز‌شده و دسترسی ریزتر اپراتورها.
- صفحات خدمات، canonical، متادیتا، Sitemap، داده ساختاریافته و noindex پنل‌ها.
- بکاپ روزانه محلی و ابزار آزمون بازگردانی روی دیتابیس مستقل.

[راهنمای امکانات، تنظیمات و محدودیت‌های نسخه](docs/OPERATIONS_V2.fa.md) را ببینید. SMTP واقعی و سرویس‌های بیرونی هنوز تنظیم نشده‌اند.

- بارگذاری اسناد خصوصی PDF/JPG/PNG، کنترل امضای فایل و حجم و دانلود با کنترل دسترسی.
- تأیید نهایی تحویل، صدور یک صورتحساب برای هر بار و ثبت دستی تسویه با مرجع.
- پشتیبانی تیکتی، پاسخ اپراتور، بستن گفت‌وگو، اعلان‌ها، گزارش و ردپای عملیات.
- پنل Django Admin روی دامنهٔ مدیریت با دسترسی کارکنان و مجوزهای جدا برای عملیات، مالی، پرونده‌ها، CRM و انتشار محتوا.

## اجرای Docker

```sh
# .env را از .env.example بسازید و رازهای تصادفی مستقل قرار دهید.
docker compose up --build --wait
docker compose exec backend python manage.py seed_content
docker compose exec backend python manage.py check --deploy --fail-level WARNING
```

لندینگ روی Next.js، پنل‌های راننده، صاحب بار و متصدی روی React و Vite و پنل مدیریت روی Django Admin اجرا می‌شوند. هر پنج بخش از بک‌اند مشترک Django و MySQL استفاده می‌کنند. نشانی‌های محلی، تنظیمات DNS و TLS، حساب‌های کارکنان و دستورهای انتشار در [راهنمای استقرار](docs/RUNBOOK.md) آمده‌اند.

این نسخه **محلی** اجرا شده است؛ دامنه فعلی `alamut.bar` تغییر یا جایگزین نشده. Docker در این دستگاه نصب نیست، بنابراین ساخت کانتینر و CI در سرویس خارجی در این نوبت اجرا نشده‌اند. اتصال واقعی پیامک، پرداخت اینترنتی، صدور بیمه، استعلام دولتی و GPS پس‌زمینه نیازمند ارائه‌دهنده، قرارداد و تنظیمات آن سرویس‌هاست؛ این موارد به‌عنوان قابلیت عملیاتی متصل معرفی نشده‌اند.
