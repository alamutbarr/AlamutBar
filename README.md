# الموت

صفحهٔ معرفی، پنل صاحب کالا، پنل راننده، مرکز عملیات و پنل متصدی روی یک Vite و یک API. جدول `shipments` بین پنل‌ها مشترک است. گفتگو فقط بین اپراتور و صاحب کالا، و بین اپراتور و راننده است (`/ws`). نقشهٔ عملیات روی `/ws/admin` است.

## راه‌اندازی

1. MySQL یا MariaDB را روی `127.0.0.1:3306` روشن کنید و یک کاربر با دسترسی ساخت دیتابیس داشته باشید. در این محیط توسعه کاربر `root` با رمز خالی کافی است.
2. از روی `.env.example` فایل `.env` بسازید. جدول‌ها با `sequelize.sync({ alter: true })` در بالا آمدن سرور ساخته و به‌روز می‌شوند. مهاجرت جداگانه‌ای نیست. اگر جدول سفارش خالی باشد، همان بالا آمدن اول دادهٔ نمونهٔ عملیات، راننده، متصدی و یک تیکت ساخته می‌شود. پرچم `demo_seeded` به‌تنهایی جلوی این کار را نمی‌گیرد.
3. وابستگی‌ها را نصب کنید و هر دو فرایند را با هم اجرا کنید.

```bash
cp .env.example .env
npm install
npm run dev
```

در توسعه، سایت روی `http://localhost:4179` و API روی `http://localhost:5088` بالا می‌آید. Vite مسیرهای `/api`، `/uploads` و `/ws` را به API می‌فرستد. تست‌های بدون دیتابیس: `npm test`.

برای همان بیلدی که منتشر می‌شود، بعد از `npm run build` دستور `npm start` را بزنید. سرور فایل‌های `dist` را هم سرو می‌کند، پس سایت و API هر دو روی پورت `5088` هستند و دانلود پرونده از همان مبدأ، با هدر `Authorization`، به API می‌رسد. پاسخ `application/pdf` است و `Content-Disposition: attachment` دارد. دکمه قبل از ساخت PDF پنجرهٔ ذخیره را باز می‌کند تا کندی Chrome (چند ثانیه برای ساخت پرونده) باعث دورریختن دانلود بی‌صدا نشود. اگر مرورگر آن پنجره را ندارد و ساخت طول بکشد، دکمهٔ «ذخیرهٔ پرونده» با یک کلیک تازه فایل را ذخیره می‌کند و در صورت برگشتن HTML به‌جای PDF پیام خطا نشان داده می‌شود. اگر فقط پوشهٔ `dist` را روی یک میزبان ایستا بگذارید و `/api` را به این سرور نفرستید، همان پیام خطا ظاهر می‌شود.

### متغیرهای محیط

| متغیر | پیش‌فرض | کاربرد |
| --- | --- | --- |
| `PORT` | `5088` | پورت API |
| `DB_HOST` | `127.0.0.1` | میزبان MySQL |
| `DB_PORT` | `3306` | پورت MySQL |
| `DB_NAME` | `alamut` | نام دیتابیس. مقدارهای قدیمی پنل‌ها را عوض نکنید |
| `DB_USER` | `root` | کاربر دیتابیس |
| `DB_PASS` | خالی | رمز دیتابیس. `DB_PASSWORD` هم پذیرفته می‌شود |
| `JWT_SECRET` | مقدار توسعه در `.env.example` | امضای توکن |
| `INSPECTOR_DEV_OTP` | `12345` | کد ثابت متصدی وقتی پیامک واقعی نیست |
| `SMS_PROVIDER` | خالی | اگر `kavenegar` باشد و `SMS_API_KEY` تنظیم شده باشد، کد ثابت کنار می‌رود |
| `SMS_API_KEY` | خالی | کلید کاوه‌نگار |
| `CHROME_PATH` | `/usr/local/bin/google-chrome` | ساخت PDF پروندهٔ مأموریت |
| `ADMIN_SEED_PASSWORD` | در توسعه `Alamut@1234` | رمز اپراتور، فقط هنگام ساخت اول حساب. در تولید بدون این متغیر حساب تازه ساخته نمی‌شود |

تا وقتی پیامک واقعی روشن نباشد، کد راننده همیشه `1234` است و کد صاحب کالا در پاسخ درخواست کد، فیلد `devOtpCode`، برمی‌گردد.

## ورود آزمایشی

ورود مرکز عملیات با نام کاربری و رمز است. رمز این شش حساب فقط بار اول که ردیف ساخته می‌شود از `ADMIN_SEED_PASSWORD` (در توسعه، اگر خالی باشد، `Alamut@1234`) گذاشته می‌شود و در بالا آمدن‌های بعدی بازنویسی نمی‌شود. پنل راننده، صاحب کالا و متصدی همچنان با کد یک‌بارمصرف است.

| نقش | مسیر | نام کاربری | رمز |
| --- | --- | --- | --- |
| مدیر سامانه | `/admin` | `admin` | `Alamut@1234` |
| اپراتور دیسپچ | `/admin` | `dispatch` | `Alamut@1234` |
| اپراتور امنیت | `/admin` | `security` | `Alamut@1234` |
| سرپرست بازرسی | `/admin` | `inspection` | `Alamut@1234` |
| پشتیبان مدارک | `/admin` | `support` | `Alamut@1234` |
| دیسپچ و امنیت | `/admin` | `shift` | `Alamut@1234` |

| نقش | مسیر | موبایل | کد |
| --- | --- | --- | --- |
| متصدی بارگیری خیام | `/inspector` | `09124000001` | `12345` |
| متصدی بارگیری عطار | `/inspector` | `09124000002` | `12345` |
| رانندهٔ نمونه | `/driver` | `09123000001` تا `09123000007` | `1234` |
| صاحب کالا، فولاد خیام | `/owner/login` | `09121111111` | `devOtpCode` در پاسخ درخواست کد |
| صاحب کالا، بازرگانی پارس | `/owner/login` | `09122222222` | `devOtpCode` در پاسخ درخواست کد |

از صفحهٔ اصلی، دکمهٔ «ورود» به راننده، صاحب کالا، اپراتور و متصدی می‌رود.

## پنل‌ها

صاحب کالا بار را ثبت می‌کند و وضعیت «در جستجوی راننده» در فهرست مأموریت راننده دیده می‌شود. از فهرست یا جزئیات بار می‌توان همان حمل را تکرار کرد و وزن، تعداد بسته، زمان و مقصد را پیش از ثبت عوض کرد. علامت «بار حساس» متصدی محل را لازم می‌کند. گفتگوی صاحب کالا با اپراتور از همان جزئیات بار باز است. راننده بعد از قبول بار فقط با اپراتور گفتگو می‌کند و عکس تحویل را روی همان مأموریت می‌فرستد. هر دو کانال گفتگو در مرکز عملیات دیده می‌شود. جایگزینی راننده و تخصیص متصدی روی صفحهٔ سفارش است.

`/api/v1/driver` برای کلاینت موبایل راننده است: OTP، مأموریت، وضعیت، مدرک، عکس و کد تحویل. توکن در هدر `Authorization: Bearer` می‌آید. گزارش موقعیت در اپ فعلاً وصل نیست؛ مسیر `POST /api/v1/driver/location` برای بعد مانده است.

`/inspector` برای متصدی میدانی است. گزارش در همان پروندهٔ بازرسی مرکز عملیات می‌نشیند. تصمیم‌های باز بخش ۱۱.۴ در تنظیمات سامانه است: `inspector_required_mode`، `inspector_dispatch_payer`، `inspector_grace_minutes`، `inspector_no_show_policy`، `weight_discrepancy_kg`، `value_discrepancy_ratio`، `inspector_final_approval`، `inspector_required_items` و `inspector_checklist`.

پرداخت و تسویه در این نسخه نیست.

## اپ راننده

اپ Expo در `mobile/driver` است و در Expo Go روی اندروید اجرا می‌شود. ورود، مأموریت، عکس دوربین و گالری، مدارک، و اجازهٔ اعلان محلی همین‌جا کار می‌کنند. ماژول بومی خارج از Expo Go ندارد.

این‌ها در Expo Go نیستند:

- پوش از سرور. از SDK ۵۳ به بعد روی اندروید در Expo Go نیست و بیلد توسعه (`npx expo run:android` یا EAS) به‌همراه شناسهٔ پروژهٔ Expo می‌خواهد. دکمهٔ اعلان در پروفایل فقط ثبت محلی می‌کند.
- موقعیت، چه پیش‌زمینه و چه پس‌زمینه. در این نسخه ساخته نشده. جای بعدی `mobile/driver/src/location.ts` است. موقعیت پس‌زمینه هم بیلد توسعه می‌خواهد، نه Expo Go.

### گوشی اندروید با Expo Go

رایانه و گوشی باید روی یک وای‌فای باشند و وای‌فای مهمان دستگاه‌ها را از هم جدا نکند. API روی `0.0.0.0:5088` گوش می‌دهد، پس از شبکهٔ محلی در دسترس است.

1. MySQL را روشن کنید و از ریشهٔ پروژه `npm run dev` را بزنید.
2. IP نسخهٔ ۴ رایانه را پیدا کنید. لینوکس: `hostname -I`. مک: `ipconfig getifaddr en0`. ویندوز: `ipconfig` و مقدار IPv4. مثلاً `192.168.1.20`.
3. از مرورگر گوشی `http://192.168.1.20:5088/health` را باز کنید. باید `{"ok":true}` بیاید. اگر نیامد، فایروال را برای پورت‌های `5088` و `8081` باز کنید.
4. Expo Go را از Play Store نصب کنید. این پروژه SDK ۵۸ است. اگر Expo Go گفت نسخه نمی‌خورد، خود Expo Go را به‌روز کنید.
5. اپ را بالا بیاورید و کد QR را با خود Expo Go اسکن کنید، نه لزوماً با دوربین گوشی.

```bash
cd mobile/driver
npm install
npx expo start
```

6. در صفحهٔ ورود، «آدرس سرور» را باز کنید. اگر Metro رایانه را دیده باشد، همان IP را با پورت ۵۰۸۸ پر می‌کند، مثل `http://192.168.1.20:5088`. اگر `127.0.0.1` ماند، آن را با IP مرحلهٔ ۲ عوض کنید و بعد «دریافت کد» را بزنید. `127.0.0.1` روی گوشی خود گوشی است و به رایانه نمی‌رسد.
7. ورود آزمایشی: `09123000001` تا `09123000007` با کد `1234`.

برای عوض کردن آدرس بدون صفحهٔ ورود، قبل از `npx expo start` این را بگذارید: `EXPO_PUBLIC_API_URL=http://192.168.1.20:5088`. حالت `--tunnel` فقط جاوااسکریپت را از اینترنت می‌آورد. API هنوز باید با IP محلی باز شود.

شبیه‌ساز وب: `npm run web` با `http://127.0.0.1:5088`. شبیه‌ساز اندروید: `http://10.0.2.2:5088`.

## ظاهر

صفحهٔ معرفی و هر چهار پنل یک پالت دارند: مرکب `#17383b`، فیروزه‌ای `#087f8c`، کرم `#f7f6f0`، طلایی `#d7b56d`، نشان کوه الموت، کارت گرد و تایپ فارسی وزیرمتن. روی عرض گوشی، صاحب کالا، راننده، عملیات و متصدی هدر فیروزه‌ای و نوار پایین شناور دارند. صفحهٔ معرفی منوی کشویی دارد، چون صفحهٔ بازاریابی است.

کلاس‌های `slate` و `blue` در فرم ورود راننده به همین پالت نگاشت شده‌اند. گوشه‌های کارت در Tailwind روی ۱۴ تا ۲۲ پیکسل است.
