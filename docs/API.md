# API contract

Base: `/api/` through the Next.js origin. OpenAPI: [openapi.yaml](openapi.yaml). Generate it with:

```sh
cd backend
python manage.py spectacular --file ../docs/openapi.yaml --validate --fail-on-warn
```

An administrative session can also open `/api/docs/`. Public API discovery does not grant data access. Responses and validation messages may be Persian. Monetary fields are integer **toman**; weight is a decimal string in **tons**; dates are ISO 8601. Lists use `{count,next,previous,results}` with page size 30.

## Session sequence

1. `GET /auth/csrf/` returns `{csrfToken,demo_enabled}` and sets a CSRF cookie.
2. `POST /auth/login/` with `{username,password,role?,code?}` and `X-CSRFToken` creates an HTTP-only session cookie.
3. Use same-origin credentials on subsequent requests. Obtain a fresh CSRF token before a mutation because login rotates it.
4. `POST /auth/logout/` with CSRF ends the session.

`POST /auth/register/` accepts `username,password,first_name,last_name,phone,role,company?`. Public roles are only `owner` and `driver`; accounts start unverified. `GET/PATCH /auth/me/` never lets clients change role or verification. `POST /auth/password/` requires `old_password,new_password`.

| `GET/PUT /vehicle/` | Driver's own vehicle; kind, plate, capacity, license_number, available |
| `GET /team/` | Operator directory of active owners/drivers/inspectors |
| `POST /team/{id}/verify/` | Operator: `{verified: boolean}`; role cannot change |
| `GET /invoices/` | Owner/assigned driver/operator; inspector gets empty list |
| `POST /invoices/{id}/settle/` | Operator; `{reference}`, 5–100 chars; duplicate denied |
| `GET/POST /tickets/` | Scoped support; create `{subject,priority,body}` |
| `POST /tickets/{id}/reply/` | Participant/operator; `{body}`; closed ticket denies replies |
| `POST /tickets/{id}/close/` | Participant/operator closes conversation |
| `GET /notifications/` | Current user's notices only |
| `POST /notifications/read_all/` | Marks only current user's notices |
| `GET /operations/` | Operator only; last 100 audit records and contact requests |
| `GET /tracking/?code=AL-...` | Public minimal tracking; no recipient or GPS data |
| `POST /contact/` | Public `{name,phone,message}`, rate limited |

Inspection `passed` is computed by the server; a client cannot declare a failed checklist successful. Latest inspection wins. The value `stage` is `loading` or `delivery`. The invoice is generated by completing a shipment and cannot be created or edited directly by a client.

## Shipment creation example

```json
{
  "title": "قطعات صنعتی",
  "origin": "تهران",
  "destination": "مشهد",
  "origin_address": "نشانی بارگیری",
  "destination_address": "نشانی تخلیه",
  "recipient_name": "گیرنده نمونه",
  "recipient_phone": "09120000008",
  "weight": "10.50",
  "vehicle_type": "trailer",
  "cargo_value": 100000000,
  "price": 12000000,
  "pickup_date": "2026-12-01",
  "notes": "هماهنگی پیش از بارگیری"
}
```

Cities must differ, the pickup date must not be in the past, weight must be positive, price at least 1,000 toman and phone `09` followed by nine digits. Status, owner, driver, inspector and code are read-only through the generic serializer. Use the authorized action endpoints for assignment and state changes.

## Error semantics

`400`: validation or invalid state; `403`: permission, authentication/CSRF or wrong role; `404`: missing or out-of-scope object; `405`: unsupported method; `429`: throttling. Session authentication returns 403 for an anonymous private request. Throttles use Redis when configured and process-local memory in development. Files have attachment disposition; CSV starts with a UTF-8 BOM for Persian Excel compatibility.

All paths below use the same session and CSRF rules. Generated schemas in openapi.yaml define request fields. Operator capability restrictions apply in addition to role checks.

Location history orders by observed_at, then receipt time. Points older than five minutes are stale in monitoring; API validation rejects far-future measurement timestamps. Role/capabilities/verified remain read-only in self-service profile updates. Recovery responses never expose tokens or account existence. SMTP configuration is an operational requirement for external delivery.

## Public editorial content

`GET /articles/?q=&page=` lists only published articles whose publication date has arrived. `GET /articles/{slug}/` returns a published guide; drafts and future articles return 404. These endpoints are read-only and do not expose the editor's account ID.

`/editorial/articles/` supports operator list/create and `/editorial/articles/{id}/` supports read/PATCH. The `content` capability is required; other operator capabilities do not imply it. Fields are title, unique ASCII slug, summary, category, plain-text body (maximum 50,000 characters), status and optional published_at. First publication assigns a date when absent. Published body must contain at least 200 characters. Returning to draft removes public visibility; deletion is not exposed. Creation/update are audited.

## Failure contract

Expected validation retains field-specific errors. Authentication errors include `code: not_authenticated`, distinct from `permission_denied`. API responses carry X-Request-ID and no-store/noindex headers. Non-JSON API 404/error responses are normalized to safe JSON. Unique/relational conflicts return 409, database availability failures 503, and unexpected failures 500 with a generic Persian detail, code and request_id. Database messages and tracebacks are not sent to clients. The browser applies a 30-second deadline, handles invalid JSON and network failures, and never retries a mutation automatically. Phone/ID/OTP Persian digits normalize in client payloads; passwords are unchanged.
