# بازبینی پنل‌ها، صفحات عمومی و برنامه‌های موبایل

سایت عمومی با Next.js و سه برنامهٔ موبایل با React و Vite اجرا می‌شوند. پنل اپراتور در Django Admin قرار دارد. نشانی‌های محلی و دامنه‌های انتشار در [راهنمای استقرار](RUNBOOK.md) آمده‌اند.

## نصب مستقل سه برنامه

از صفحهٔ [پنل‌ها و نصب برنامه](http://127.0.0.1:3001/apps) نقش مناسب را باز کنید:

| برنامه | مسیر شروع | محدوده و شناسه نصب |
| --- | --- | --- |
| صاحب بار | `/owner/app` | `/owner/` |
| راننده | `/driver/app` | `/driver/` |
| متصدی | `/inspector/app` | `/inspector/` |

هر برنامه manifest، نام، رنگ، آیکون ۱۹۲ و ۵۱۲ پیکسل و آیکون maskable جدا دارد. ورود همان نقش در مسیر شروع برنامه انجام می‌شود؛ لینک قدیمی ریشهٔ پنل به مسیر شروع هدایت می‌شود. حساب نقش دیگر، پیام روشن و گزینهٔ خروج و تعویض نقش می‌گیرد. اپراتور و متصدی ثبت‌نام عمومی ندارند.

روی Android از Chrome/Edge و گزینهٔ Install app استفاده کنید. روی iPhone/iPad، در Safari از Share و Add to Home Screen استفاده کنید. دکمهٔ نصب فقط در صورت پشتیبانی مرورگر، پنجرهٔ نصب بومی را باز می‌کند؛ در غیر این صورت راهنمای همان روش نمایش داده می‌شود.

نصب روی گوشی واقعی به دامنهٔ HTTPS قابل دسترسی نیاز دارد. هر برنامه نشست مستقل روی زیردامنهٔ خودش دارد. برای هر نقش از حساب همان نقش استفاده کنید.

## چیدمان موبایل

ناوبری پایین برای هر نقش متناسب با کار روزانهٔ آن تنظیم شده است. «خانه» و «بیشتر» در همهٔ پنل‌ها در دسترس‌اند. اعلان‌ها و حساب کاربری از سربرگ باز می‌شوند.

| نقش | دسترسی‌های اصلی موبایل |
| --- | --- |
| صاحب بار | محموله‌ها، ثبت بار و امور مالی |
| راننده | سفرهای من، بازار بار و مدارک |
| متصدی | محموله‌ها، مأموریت‌های بازرسی و رخدادها |

فهرست محموله‌ها، صورتحساب‌ها، CRM، ناوگان و گزارش موقعیت در موبایل به شکل کارت نمایش داده می‌شوند. فرم حمل به چهار بخش مرتب شده است. فرم‌های عملیات و منوی «بیشتر» از پایین باز می‌شوند. جزئیات بازار بار و بازرسی دکمهٔ بازگشت به فهرست همان بخش دارند. در صفحات عمومی، نوار پایین به خانه، خدمات، پیگیری بار و ورود به پنل‌ها می‌رسد.

برای بازاجرای آزمون مرورگر، با دادهٔ نمونه در محیط محلی و از پوشهٔ `frontend` اجرا کنید.

```sh
npx playwright install chromium webkit
npm run test:mobile
```

## آفلاین و به‌روزرسانی

- فقط صفحهٔ راهنمای آفلاین، آیکون‌ها، فونت و فایل‌های عمومی مجاز برنامه کش می‌شوند.
- API، صفحهٔ خصوصی HTML، پاسخ RSC، مدارک، پیام‌ها، پرداخت‌ها و موقعیت در کش برنامه قرار نمی‌گیرند.
- در قطع شبکه، ناوبری به صفحهٔ آفلاین عمومی می‌رسد. این صفحه اطلاعات خصوصی یا تصویر قدیمی از وضعیت بار نشان نمی‌دهد.
- ثبت بار، پرداخت یا تغییر وضعیت در صف آفلاین نگه داشته نمی‌شود. پس از خطای شبکه، پیش از تکرار ثبت، وضعیت قبلی را بررسی کنید.
- هر build شناسهٔ انتشار تازه‌ای در worker قرار می‌دهد. نسخهٔ جدید، پیام «به‌روزرسانی و بارگیری دوباره» نشان می‌دهد؛ پس از ذخیرهٔ فرم آن را بزنید. فرم تغییرکرده در بارگیری مجدد می‌تواند هشدار خروج مرورگر بدهد.
- برای جلوگیری از تداخل توسعه، فایل‌های Next.js با URL ثابت و بدون هدر immutable به کش پایدار وارد نمی‌شوند. دارایی‌های عمومی کش‌شده محدودند و کش نقش دیگر با به‌روزرسانی یک برنامه حذف نمی‌شود.
- رصد مکان همچنان به اجازهٔ راننده، صفحهٔ باز و دستگاه فعال وابسته است. نصب PWA، GPS پس‌زمینه، پیامک یا اعلان Push بیرونی را فعال نمی‌کند. اعلان داخلی سامانه موجود است.

## اصلاحات حاصل از بازبینی پنل‌ها

| مورد پیدا‌شده | رفتار اصلاح‌شده |
| --- | --- |
| مسیر ناشناخته یا صفحهٔ نقش دیگر به صفحهٔ خالی می‌رسید | ترکیب نقش، بخش و شناسه قبل از نمایش کنترل می‌شود؛ مسیر نامعتبر پاسخ واقعی ۴۰۴ می‌دهد |
| خطای شبکه در بررسی حساب شبیه خروج از حساب بود | خطای شبکه از پایان نشست تفکیک شده و همان صفحه تلاش مجدد دارد |
| پاسخ دیررسِ صفحهٔ قبلی می‌توانست دادهٔ صفحهٔ تازه را عوض کند | بارگیری اصلی با شناسهٔ درخواست کنترل و پاسخ‌های قدیمی کنار گذاشته می‌شوند |
| تازه‌سازی بعضی بخش‌های مستقل عمل نمی‌کرد | CRM، اتاق کنترل، مدارک، امنیت، رخدادها، نشانی و مقالات به تازه‌سازی پنل متصل‌اند |
| تیکت با خطای سرور در ظاهر بسته می‌شد | رابط فقط پس از تأیید سرور وضعیت بسته را اعمال می‌کند |
| خروج از حساب در مسیر شروع می‌توانست نمای قبلی را نگه دارد | پس از خروج موفق، مسیر ورود همان برنامه دوباره بارگیری می‌شود |
| دسترسی محدود اپراتور، لینک‌های بدون مجوز می‌دید | منو، اقدام بررسی کاربران، خروجی گزارش و مسیر پیشنهادی داشبورد با مجوز هماهنگ شده‌اند |
| خواندن جدول در عرض کم سخت بود | رکوردها به کارت‌های دارای برچسب تبدیل شدند و جزئیات هر ردیف در همان کارت قرار گرفت |
| منوی موبایل برای صفحه‌کلید کامل نبود | منو در پنجرهٔ بومی مرورگر باز می‌شود و با Escape و بازگرداندن فوکوس به «بیشتر» کار می‌کند |
| یافتن کاربر در فهرست ناوگان سخت بود | جست‌وجوی نام، موبایل، نام کاربری و پلاک و فیلتر نقش اضافه شد |
| شمارهٔ فارسی ممکن بود در اعتبارسنجی مرورگر رد شود | الگوی ورودی و تبدیل پیش از ارسال تکمیل شد؛ رمز عبور تبدیل نمی‌شود |
| خرابی API می‌توانست پاسخ HTML یا خطای فنی نشان دهد | پاسخ JSON امن، پیام قابل اقدام، کد پیگیری و مدیریت زمان پاسخ اضافه شد |

هیچ عملیات تغییردهنده به‌صورت خودکار تکرار نمی‌شود. پاسخ نامشخص، به معنی ثبت‌نشدن قطعی نیست. خطای شبکه، timeout، پایان نشست، نداشتن مجوز، پیدا نشدن داده، محدودیت تعداد درخواست، فایل حجیم و خطای سرویس پیام مناسب دارند. خطاهای پیش‌بینی‌نشده جزئیات دیتابیس یا traceback را به کاربر برنمی‌گردانند.

## صفحات عمومی

صفحات درباره ما، فهرست خدمات، روش همکاری، مقالات، پرسش‌های قابل جست‌وجو، تماس، پیگیری، راهنمای نقش‌ها، نصب برنامه، امنیت، شرایط استفاده، حریم خصوصی و وضعیت سرویس با ناوبری مشترک اضافه یا تکمیل شده‌اند. ظاهر فارسی و واکنش‌گراست و صفحات دارای عنوان، توضیح و canonical هستند.

فرم تماس واقعاً سرنخ CRM می‌سازد. پیگیری عمومی فقط شهرها، وضعیت و زمان تغییر را نشان می‌دهد. وضعیت سرویس یک بررسی لحظه‌ای اتصال است و ادعای SLA یا تاریخچه دسترس‌پذیری ندارد. اطلاعات تجاری و مجوزهای تأییدنشده، شماره تماس ساختگی و آمار مشتری ساختگی اضافه نشده‌اند.

## مدیریت مقالات

اپراتور دارای مجوز `content`، از «مقالات و محتوا» مقاله می‌سازد یا ویرایش می‌کند. عنوان، نشانی انگلیسی یکتا، خلاصه، دسته، متن و وضعیت لازم‌اند. پیش‌نویس در API و سایت عمومی قابل دریافت نیست. انتشار به متن حداقل ۲۰۰ نویسه و تاریخ انتشار نیاز دارد؛ در انتشار نخست تاریخ خودکار ثبت می‌شود. بازگرداندن به پیش‌نویس مقاله را از دسترسی عمومی خارج می‌کند. تاریخ انتشار آینده از API پشتیبانی می‌شود و تا سررسید عمومی نیست.

محتوا متن ساده است. برای تیتر بخش، خط را با `## ` شروع کنید. HTML واردشده به عنوان متن نمایش داده می‌شود و اجرا نمی‌شود. انتشار و ویرایش ردپای عملیات دارند. دسترسی `content` از پنل فنی مدیر تعیین می‌شود؛ مهاجرت فقط به اپراتورهایی که همهٔ مجوزهای قبلی را داشتند این مجوز را اضافه می‌کند و مجوز اپراتور محدود را گسترش نمی‌دهد.

چهار راهنمای اصلی برای درخواست بار، مدارک راننده، موقعیت و بازرسی نوشته شده‌اند. نصب تازه می‌تواند آن‌ها را با فرمان زیر ایجاد کند؛ این فرمان تغییرات سردبیر را بازنویسی نمی‌کند:

```powershell
backend/.venv/Scripts/python.exe backend/manage.py seed_content
```

در Docker: `docker compose exec backend python manage.py seed_content`.

## بررسی و حدود تحویل

گزارش شمارش تست‌ها و شواهد در [VERIFICATION.md](VERIFICATION.md) است. بازبینی مرورگر ۴۱ مسیر منوی چهار نقش و ۱۳ صفحهٔ عمومی را پوشش داد. این بررسی، تضمین نبود همهٔ باگ‌های ممکن، آزمون بار سنگین یا گواهی مستقل امنیت و دسترس‌پذیری نیست.

سرویس‌های بانکی، بیمه، استعلام دولتی، پیامک و SMTP واقعی و دامنهٔ عمومی همچنان به پیکربندی ارائه‌دهنده نیاز دارند. متن‌های عمومی باید هنگام بهره‌برداری با اطلاعات واقعی کسب‌وکار و سیاست نگهداری داده تکمیل شوند.

منابع فنی PWA: [راهنمای رسمی Next.js](https://nextjs.org/docs/app/guides/progressive-web-apps)، [شناسه برنامه در MDN](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Manifest/Reference/id)، [محدوده برنامه در MDN](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Manifest/Reference/scope).
